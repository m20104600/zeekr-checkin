# 青龙安装：一个订阅，六条独立定时任务

本说明适用于公开仓库 `m20104600/zeekr-checkin` 的 `main` 分支。

**安装入口是「订阅管理 → 创建订阅」，不是「定时任务 → 新建」粘贴网址。** 订阅负责下载脚本、自动导入任务；六条任务分别负责签到或补领，之后可在面板单独编辑。

## 一、开始前准备

1. 准备能访问 GitHub 和极氪接口的青龙环境，建议 Node.js 18+。
2. 面板/容器调度时区设为 **`Asia/Shanghai`（UTC+8，北京时间）**，核对面板显示的下次运行时间。本文所有默认时间均为 UTC+8；电脑/浏览器时区不会替你修改容器调度时区。
3. 准备本人的完整 Bearer Token：可以使用自己部署的 [zeekr-token-web](https://github.com/m20104600/zeekr-token-web)，也可以从本人极氪 App 的请求头 `Authorization` 获取。本项目不提供公共在线取 Token 服务；部署和使用登录工具请看它的独立仓库。
4. 如果已有旧的极氪任务，**先禁用旧手动任务及旧订阅**，保留原有环境变量凭据。不要同时启用新旧两套，也不要重复创建本仓库订阅。

六个入口都是**自包含 JS 脚本**，不需要 npm 包，不需要将共享文件填写到「依赖文件」。青龙没有手机代理客户端的 MITM 抓取环境，不会自动从你的手机获取 Token。

## 二、保存 Token（环境变量，不是任务命令）

打开青龙 **环境变量 → 新建变量**：

| 字段 | 内容 |
|---|---|
| 名称 | `ZEEKR_TOKEN` |
| 值 | `<自己的完整Bearer Token>`（实际值必须包含 `Bearer ` 前缀） |
| 备注 | 自行填写，例如「极氪主账号」 |
| 状态 | 启用 |

请把占位文字替换为自己的实际值，**不要把尖括号、变量名 `ZEEKR_TOKEN=` 或引号一起粘进值**。Token 仅保存到自己的青龙环境变量，不写到脚本、仓库链接、任务命令或公开配置中。

### 多账号（可选）

建议按账号分别新建启用的变量：

- `ZEEKR_TOKEN_1`：第一个账号的完整 Bearer Token。
- `ZEEKR_TOKEN_2`：第二个账号的完整 Bearer Token。
- 更多账号继续使用数字后缀。

每个变量值只放该账号自己的 Token。不要又在 `ZEEKR_TOKEN` 中重复填入相同账号，避免一个任务内重复执行。也兼容 `ZEEKR_TOKEN` 换行分隔多个 Token 及 `ZEEKR_VAL` JSON；新手优先采用数字后缀方式。

可选昵称：`ZEEKR_NICKNAME_1`、`ZEEKR_NICKNAME_2`，与凭据后缀对应；也支持 `ZEEKR_NICKNAMES` JSON 数组，例如 `["主账号","家人"]`。优先级为单独昵称变量 → 昵称数组 → Token 中昵称 → userName；没有昵称时只显示账号 ID。昵称不影响登录和调度。

## 三、创建唯一的仓库订阅

打开 **订阅管理 → 创建订阅**，按下表填写。部分版本字段布局不同，以同名或同义字段为准。

| 字段 | 填什么 | 说明 |
|---|---|---|
| 名称 | 极氪签到 | 订阅名称，不是某一场任务的名称 |
| 类型 | 公开仓库 | 不选单文件下载 |
| 链接 | `https://github.com/m20104600/zeekr-checkin.git` | 仓库地址，不是网页文件链接或 raw JS 链接 |
| 分支 | `main` | 不要留成其他分支 |
| 白名单 | `zeekr_.*\.js$` | 只导入六个专用入口 |
| 黑名单 | 留空 | 避免误排除入口 |
| 依赖文件 | 留空 | 脚本自包含，无需依赖文件 |
| 文件后缀（若显示） | `js` | 本次导入 JS 脚本 |
| 自动添加任务 | 开启 | 关闭后不会自动建立六条任务 |
| 自动删除任务 | 建议关闭 | 防止错误配置时误删任务；将来清理旧任务需自行核对 |
| 定时规则 | `23 4 * * *` | 每天 04:23 更新仓库，不是签到时间 |

方便复制的仓库地址：

```text
https://github.com/m20104600/zeekr-checkin.git
```

白名单直接复制以下内容，**不加引号，不加 `/…/`，反斜杠保留一个**：

```text
zeekr_.*\.js$
```

订阅的定时规则只填这一条：

```text
23 4 * * *
```

> **两个「定时」不能混淆：**「订阅管理」的 `23 4 * * *` 是更新脚本的时间；「定时任务」中各自的六条 cron 才是签到/补领时间。订阅规则无需填写六场时间，更不需要创建六个相同仓库订阅。

## 四、保存并首次导入

1. 保存订阅。
2. 在「订阅管理」找到「极氪签到」，点 **运行一次**（部分版本显示「运行」）。
3. 查看这次订阅日志，等待仓库下载和自动添加任务完成。失败时先处理下载/过滤/导入问题，不要用重复建订阅来重试。
4. 打开 **定时任务**，搜索 **极氪**，核对下表六条任务及其本地脚本路径。

**这次运行的是订阅更新，不是业务任务。** 它只下载/更新脚本并导入任务，不会直接签到、上报步数或领取。导入并启用后的任务会在各自计划时间运行；若恰好临近计划时间，也可能随后正常触发。

| 稳定任务名称 | 时间（UTC+8） | 默认 cron | 仓库内脚本 | 固定模式 | 固定场次标签 |
|---|---|---|---|---|---|
| 极氪签到·凌晨场 | 00:01 | `1 0 * * *` | `qinglong/zeekr_0001_all.js` | `all` | 凌晨场 |
| 极氪签到·凌晨补领 | 00:10 | `10 0 * * *` | `qinglong/zeekr_0010_claim.js` | `claim` | 凌晨场·补领 |
| 极氪签到·早间场 | 08:10 | `10 8 * * *` | `qinglong/zeekr_0810_all.js` | `all` | 早间场 |
| 极氪签到·早间补领 | 08:20 | `20 8 * * *` | `qinglong/zeekr_0820_claim.js` | `claim` | 早间场·补领 |
| 极氪签到·晚间场 | 21:30 | `30 21 * * *` | `qinglong/zeekr_2130_all.js` | `all` | 晚间场 |
| 极氪签到·晚间补领 | 21:40 | `40 21 * * *` | `qinglong/zeekr_2140_claim.js` | `claim` | 晚间场·补领 |

- `all`：完整流程，包括签到、步数、任务与领取。
- `claim`：仅领取，补收稍后入账的奖励，不重新跑完整签到流程；不保证服务端一定已经生成奖励。
- **模式与标签由每个入口固定，无需设置全局 `MODE` / `TAG` 或 `ZEEKR_MODE` / `ZEEKR_TAG`。** 不要试图用全局模式将这六条一起改成主任务或补领。
- 任务命令应为青龙生成的 **`task` 加本地脚本路径**。实际目录前缀由面板、订阅及版本决定，不在此提供固定前缀；保留面板生成值，末尾应指向表中的对应脚本。
- **网页 URL 不是任务命令。** 不要将 GitHub、raw 或 CDN 下载地址粘进命令字段。

如需立即验收，可由账号本人手动运行一条 `all` 主任务并查看日志；这是实际签到、上报和领取，不是离线检查。无需为了确认导入成功把六条连续点一遍，也不应同时启动多条。

## 五、单独修改时间、启用或禁用

在 **定时任务 → 找到对应任务 → 编辑 → 定时规则 → 保存** 修改，不是在订阅里改。

cron 五段依次为「分 时 日 月 周」：

- `1 0 * * *`：每天 00:01。
- `30 8 * * *`：每天 08:30，可用来替换早间主任务默认的 08:10。
- `40 8 * * *`：每天 08:40，可独立给早间补领使用。

主任务与补领分别编辑，建议让补领在对应主任务完成后再执行，避免重叠。改时间不改变入口固定的场次标签，例如将早间任务挪到 08:30 后仍标记为「早间场」。不需要某一场时，在列表禁用那一条即可，其他五条不受影响。

更新时仍运行**原来的同一订阅**，保留相同入口路径。重新拉取应保留面板里已修改的 cron 和禁用状态；不要为了更新而删除重建订阅、移动/改名入口，或手动复制出第二条同路径任务。不同面板版本、二次修改和本地配置可能影响导入行为，更新后请再次核对六条任务、下次运行时间及启用状态；这里不承诺所有青龙版本或你的实际面板均已测试。

## 六、旧版迁移与版本范围

- 旧 `dist/zeekr.qinglong.js` 通用脚本仍可供原有手动任务使用，但不是自动六任务入口，**不要把它加入本订阅白名单**。
- 采用新方案前禁用旧手动极氪任务及旧订阅，确认仅保留一组新任务运行。旧订阅只禁用还不够：它已经导入的旧定时任务也要单独禁用。
- 保留环境变量，不要删除或公开已有凭据；旧账号可直接复用正确启用的 Token 变量。
- 看到重复项先比对命令中的实际路径和来源，不按显示名称直接批量删除。建议订阅关闭「自动删除任务」，因此旧入口的清理需要人工核对。
- **v3.3.0（2026-10-28，UTC+8）**：将实验仓库中已由维护者验证的青龙和 Egern 改动合回本仓库，核心、手机脚本和青龙订阅入口统一更新。升级后刷新/重新导入本仓库配置，勿同时启用实验仓库的同一套任务。
- 本次更新手机与青龙的脚本及配置，不修改独立 MPv3 插件和本机 timer。

## 七、常见问题（按顺序排查）

### 1. 保存了订阅，为什么没有六条任务？

1. 保存不等于已经拉取：在原订阅点「运行一次」，查看本次日志。
2. 确认类型是公开仓库，链接和 `main` 分支正确；拉取失败先查 GitHub 网络。
3. 白名单应为 `zeekr_.*\.js$`，没有引号、没有多余反斜杠；黑名单和依赖文件留空。
4. 确认「自动添加任务」开启，若显示文件后缀则填写 `js`。
5. 确认日志中存在六个 `qinglong/zeekr_*.js`，再到定时任务搜索「极氪」，检查筛选条件是否隐藏了禁用任务。
6. 如果此前删除过自动任务，检查该面板版本的忽略/禁止再次添加设置；按该版本界面恢复后重新运行原订阅。不要反复新建相同订阅。
7. 仍不符合时，提供面板版本、脱敏订阅字段及导入日志，不要提供 Token。

### 2. 为什么出现两组任务、一次收到多条重复结果？

检查是否同时存在旧通用脚本手动任务、旧仓库订阅、重复的新仓库订阅，或手动复制任务。按本地脚本路径逐条识别，禁用多余的旧任务和对应旧订阅，只留一组新六条。也检查同一账号是否同时配置了无后缀和有后缀的 Token。不要为清理重复任务删除凭据。

### 3. 提示缺少 Token，或鉴权失败？

核对环境变量拼写、启用状态和实际值：是否复制完整 `Bearer ` 前缀，是否仍为占位符，是否把变量名或引号一并粘入。Token 可能被撤销，也可能平台不匹配，不能把所有鉴权失败都称为过期；必要时重新获取本人的 Token。解码得到到期日也不等于服务端仍接受它。不要在公开截图、日志、Issue 中展示完整 Token。

### 4. 补领任务为什么跑成主签到，或场次标签错误？

先核对命令的文件末尾：补领应为 `_claim.js`，主任务应为 `_all.js`。如果还指向 `dist/zeekr.qinglong.js`，那是旧通用任务，不是新六入口。新入口固定模式和标签，不需要全局 `MODE` / `TAG`；不要靠改全局变量来补救错误路径。重新运行原订阅，核对六条命令来源。

### 5. 网络错误、拉取失败、超时怎么区分？

- **订阅日志下载失败**：检查青龙服务器到 GitHub 的 DNS、TLS、网络连接及仓库地址，与 Token 无关。
- **任务能启动，但接口请求失败**：检查青龙服务器到极氪接口的网络及服务端响应；浏览器能访问不等于容器能访问。
- **鉴权业务码失败**：看脱敏业务码和提示，按凭据/平台问题排查，不要当成 GitHub 下载失败。
- **等待或轮询超时**：查看是否自行启用了 `ZEEKR_POLL`、额外等待等参数及面板执行超时；不要无条件重跑六条来排查。

### 6. 命令填了 JS 下载 URL，提示文件不存在或命令找不到？

下载 URL 只能用于下载文件，不能直接执行。回到「订阅管理」按本文创建/运行仓库订阅，使用自动生成的本地 `task` 命令。不要照抄其他面板的固定目录前缀。

### 7. 改时间后看起来没生效，或者更新后状态变化？

确认改的是「定时任务」对应那一条，而不是订阅更新的 `23 4 * * *`；核对 `Asia/Shanghai`、保存结果、任务启用状态及下次运行时间。更新时使用原订阅、原路径；如果删除重建、入口路径改变或面板版本行为不同，先核对实际任务再调整，不要继续叠加新订阅。

## 八、安全与验收边界

本文不需要任何真实账号示例，也不提供公共登录工具地址。Token、短信验证码、手机号、设备凭据不得提交到 Git 或公开工单。反馈时仅保留必要的脱敏日志。

自动导入六条任务仅证明调度配置建立，不等于 Token 有效、真实签到成功或奖励到账。接口返回成功也不代表奖励已生成；应由账号本人分别核对日志和 App 状态。不要把导入检查、模拟测试或某个版本的离线测试说成所有青龙版本及实际用户面板都已实测通过。
